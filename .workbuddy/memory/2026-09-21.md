## 本轮新踩的坑（重要，已全部写进 docs/refactor-roadmap.md 第六节）
1. **HTTP 方法矩阵**：原版 `app.use(route)` 是全方法挂载，我最初写成 GET-only → `POST /login/cellphone` 直接 404。改为 `method: ['GET','POST','PUT','DELETE','PATCH']`（HEAD 由 Fastify 从 GET 派生）。**教训：GET 回归全绿不代表接口等价——方法维度必须单独测**，已固化成契约 C11。

4. `disableRequestLogging` 在 Fastify 5.12 已废弃 → 删掉，需要日志时 `logger: true`（逐请求日志本就由 `LOG_REQUESTS` 分支自己打印）。
5. mocha 加载 `.ts` 引导文件会打 `MODULE_TYPELESS_PACKAGE_JSON` 警告 → `.mocharc.json` 用 `node-option: ["import=tsx"]`（注意 `--import tsx` 直接传给 mocha 会被当成相对路径解析失败）。
6. `npm run lint` 一旦把 `scripts/**/*.cjs` 纳入范围，基础规则（indent/quotes）会报 89 个可自动修的错 → `npm run lint-fix` 一把修完，注意修完要重跑脚本确认没改坏。
7. 无类型包 `safe-decode-uri-component` 没有 `@types` → `src/shims.d.ts` 声明 `export =`，改用 `import`；浏览器全局（`async`/`cookieGet`/`cookieRemove`）也用 `declare` 收口。
8. **沙箱出网**：Bash 工具里 `(npm start &)` 拉起的服务出网被拦（报 `upstream connect failed: Connection refused (os error 61)`），必须用 `run_in_background: true` 启动，否则会误判成「上游挂了」。

# 新旧架构逐接口性能对照（Express vs Fastify）

## 做法
- 旧版从 git 导出：`git archive HEAD | tar -x -C /tmp/ncm-legacy` + 软链本项目 `node_modules`，`PORT=3101 node app.js` 与 `PORT=3102 node dist/main.js` 并行常驻
- 新脚本 `scripts/bench-compare.cjs`：单轮 cold+warm 采集 / `--sweep` 逐接口并发扫描 / `--load` 峰值压测 / `--merge` 合并出报告
- 编排脚本 `scripts/bench-all.sh`：同一条命令内启停两版 + 3 轮采集 + sweep + 压测 + 出报告（沙箱会回收命令结束后的残留后台进程，必须同生命周期）
- 产物：`docs/perf-comparison.md`（495 行报告）、`docs/perf-comparison.json`、原始数据 `docs/perf-raw/{round-1..3,sweep,load}.json`

## 结论
| 口径 | 旧 | 新 | 变化 |
|---|---|---|---|
| cold（含上游） | 82.35 ms | 79.32 ms | +3.7%（上游主导，视为持平） |
| 框架纯开销（命中缓存、零上游） | 0.631 ms | 0.442 ms | +30% |
| 4 并发逐接口吞吐（154 条可比） | 12585.7 rps | 21355.8 rps | **中位数 +68%**，149 条变快 |
| 32 并发峰值（6 条典型） | — | — | +29.7% ~ +65.6% |
| 常驻内存 | 47.8 MB | 99 MB | schema 12MB / 方法矩阵 5MB / swagger 1MB / 其余框架固有 |
| 冷启动 | 484 ms | 684 ms（dist） / 969 ms（tsx） | 线上必须用 dist，别用 tsx |

## 修掉的两个「命中路径」性能坑（`src/core/cache.ts` + `src/app.ts`）
1. `onSend` 在缓存命中路径仍执行回写 → 每次命中都做一次全文长度扫描 + Map 覆写。修法：`onRequest` 命中时给 req 打 `cacheHit` 标记，`onSend` 据此跳过。
2. 缓存存的是字符串 → 每次命中都要把整个响应体重新 UTF-8 编码。修法：只存预编码 `Buffer`，写入时用 `buf.length` 判容量（顺带省掉 `Buffer.byteLength`、内存减半）。
- 效果：`/toplist`（80 KB）3564 → 14301 rps，即 **-57.3% → +29.8%**。修复前它是全表唯一负分项。

## 方法学教训（已固化为 skill `refactor-perf-ab-benchmark`）
- **单发顺序请求测不出框架差异**：Node 客户端每次 fetch 固定开销 0.3~0.5 ms > 服务端差异，单发口径曾显示「新架构慢 13%」，同代码并发口径是 +68%。判定框架速度必须用固定并发扫描。
- **「路由可缓存」≠「这次命中缓存」**：301/404/502 都不写缓存，用白名单筛选会把回源样本算进「框架开销」，均值直接变负。按 `warm < cold × 0.4` 实测判定。
- **短采样噪声可达 2 倍**：4 条首轮显示「退化」的接口，5 次 ×1.2s 重采后全部转正（-42% → +9.2%，-39.7% → +66.8%）。整体结论一律看中位数。
- 每轮采集前重启两版服务保证 cold 纯净；逐轮交换请求先后抵消上游漂移。

## 事故（已修复）
测启动时间时用了 `pkill -f "tsx src/main.ts"`，**误杀用户在 3000 端口手动起的 `npm start` 服务**。已重新拉起（PID 63593，`/healthz` routes=281 正常）。教训：kill 只匹配自己起的 PID，别用宽泛的模式匹配（本机 3000 端口是用户的 dev 实例，3101/3102 才是我起的对照实例）。

# 第二轮：启动/内存优化（用户追问「有使用按需加载路由的架构吗」）

## 硬约束（实测，不是推测）
Fastify **不允许 `ready()` 之后追加路由**，抛 `AVV_ERR_ROOT_PLG_BOOTED`。所以「按需注册路由」做不到；
但路由表只需要**路径字符串**，而本项目「路径即路由」（由文件名推导）→ 建表不需要读模块。
于是拆成：启动只注册路径 + 惰性 handler，281 个模块**首次命中该路由**才 `require`。
官方 `@fastify/autoload` 不解决这个问题（它仍是启动即全量 require，且要求把 281 个文件改成插件形态 → 会动业务代码，未采用）。

## 三轮改动（都只改「何时加载」，不改业务语义）
| 阶段 | 冷启动 spawn→/healthz | 内存 | ready() |
|---|---|---|---|
| 初始态（全量加载 + ajv） | 524.5 ms | ~95–99 MB | ~102 ms |
| + 路由惰性加载 | 433.9 ms | ~91–93 MB | ~102 ms |
| + 去掉 ajv 校验编译 | 282.8 ms | ~78–80 MB | 4.9 ms |
| + 可选依赖移出启动路径（现状） | **224.8 ms** | **64–67 MB** | 3.3 ms |
累计 **-299.7 ms（-57%）/ -30 MB（-32%）**。

1. **`src/core/routes.ts` 改惰性**：`loadRoutes()` 返回 `{identifier, route, file, resolveHandler}`；失败也缓存。
   `app.ts` 里 `def.resolveHandler()` 必须放在业务 `try/catch` **之外**（那个 catch 会把异常当 module 错误响应 → `!body` 时回 404，会把「模块坏了」静默降级成「路由不存在」）。`src/index.ts` 编程式 API 同步惰性。
2. **schema 只喂文档，不参与校验**（`app.ts`）：`schemaController.compilersFactory.buildValidator` 换恒真函数。
   顺带修掉一个**重构引入的行为偏差**：ajv 默认 `coerceTypes`，`?id=1&id=2`（数组）被判非法 → **400**，
   旧版 Express 是 **200**。267 条回归全是单值参数，**覆盖不到**。已固化契约 **C13**。
   `buildValidator` 的类型签名要求 ajv `ValidateFunction`，恒真函数必须显式断言，否则 TS 回退到 http2 构造函数重载（报 `app.server` 是 `Http2SecureServer` 等无关错误）。
3. **可选依赖移出启动路径**：`pac-proxy-agent`（108 ms/+24 MB，仅 `?proxy=pac://`）、`tunnel`（仅 `?proxy=http://`）、
   `@fastify/compress`（仅 `ENABLE_COMPRESS=1`）。启动路径模块数 748 → 549。代理两分支已实测（tunnel 200 走真实代理 / pac 502 走原错误路径）。
   注意：缓存键把 `proxy` 当 VOLATILE 参数 → 第二次请求会命中缓存、像「瞬间成功」，必须换未缓存参数值才能真的走到分支。

## 教训
- **管道吞退出码**：`npm run typecheck 2>&1 | tail -5` 的 `$?` 是 tail 的 0，会在类型已报错时误判「通过」。门禁命令要么不接管道，要么重定向后单独 `echo $?`。
- 惰性化一个启动期模块后**别只跑回归就宣布完成**：失败点从启动挪到了首次请求，必须对那条链路打真实请求。
- 别用 `grep` 的 `\|` 交替（macOS BSD grep 不支持），会静默返回空 → 用 `grep -E` 或 Grep 工具，否则会把「没匹配」误读成「没有残留」。
